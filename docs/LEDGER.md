# The campaign ledger (verbatim, Korean)

This file is the campaign's working ledger — the primary record every number and
every verdict in this repository resolves to. It is kept in the original Korean,
unedited, because it is the source of truth rather than a presentation of it. The
structure is AIF (my note convention for model-facing documents): `[I#]` are
information nodes (measured facts), `[RA#]` are inference nodes (reasoning from
facts), `[CA#]` are conflict nodes (claims that were overturned — kept, not
deleted, with what overturned them), and `[PA#]` are decision nodes. Sections were
appended chronologically as the campaign ran, so reversals appear *after* the
verdicts they reverse; `[CA#]` nodes are the map of where my earlier conclusions
broke. Operational data (commands, paths, hosts) lives in plain blocks at section
ends. One mechanical concession to GitHub's renderer: bare tildes in numeric
ranges (e.g. 2.3\~2.5) are backslash-escaped so GFM does not pair them into
strikethrough — the rendered text is the original; the prose is otherwise
byte-identical to the working ledger. The English topical documents in this directory are distilled from this
ledger; where they disagree, the ledger wins.

# DSpark 드래프터 MLX 이식 — 판정 노트 (2026-08-15)

## 정보 노드

- **[I1]** `RadixArk/Qwen3.8-27B-DSpark` = DFlash 백본 + Markov/confidence 헤드.
  1.359B · 5층 · GQA 40q/8kv · 블록 7 · 타깃 보조층 [4,16,28,40,52] · mask_token 248077.
  카드 수락 길이: 전체 평균 3.39(HumanEval 3.47), FP8 타깃 · SGLang · temp 0.6 기준.
- **[I2]** 알고리즘은 **블록 디퓨전**이다. 7슬롯을 순차가 아니라 한 번의 forward 로
  병렬 생성하고, 어텐션은 `[타깃 컨텍스트 K/V ‖ 블록 K/V]` 이중 소스, 블록 내부는
  양방향(`is_causal=False`). 드래프터는 embed/lm_head 를 갖지 않고 타깃 것을 빌린다.
- **[I3]** MLX 이식(`mlx_lm/models/dspark.py`)은 PyTorch 참조와 **수치 동치**다 —
  코사인 1.00000000, 최대 절대오차 1.1e-4(float32), 파라미터 1.359B 일치.
- **[I4]** 타깃 중간층 탭 배선(`qwen3_5` 의 `tap_layers`)은 반환 시그니처를 바꾸지 않아
  기존 생성·서버·MTP 경로에 영향이 없다.
- **[I5]** 투기 루프는 무손실이다 — 평문 그리디와 64/64 일치(수락률이 낮던 시점 기준).
- **[I6]** 수락 길이 실측: 4bit 타깃 코드 2.3\~2.5 · 한국어 1.9\~2.2, 8bit 타깃 최대 2.68.
  카드 3.39 보다 낮다(카드는 FP8 타깃 + temp 0.6 기각-샘플링, 우리는 4/8bit + 그리디).
- **[I7]** **타깃 forward 는 토큰 수에 평평하지 않다**(4bit, M3 Ultra):
  S=1 29.7ms · S=2 32.1 · S=4 45.4 · S=7 62.5 · S=12 103.8 · S=16\~32 ≈105 · S=64 193.
  한계비용 ≈5ms/토큰.
- **[I8]** 이 증가는 선형-어텐션 커널 고유가 아니다 — 선형층 S=7/S=1 = 1.71×,
  풀어텐션층 1.80× 로 **양쪽이 같이 는다**. 4bit qmm 실효 ≈12 TFLOPS(bf16 GEMM 상한
  22.45 의 절반)와 정합한다. 즉 컴퓨트이지 고칠 커널 결함이 아니다.
- **[I9]** 스텝 구간 계측(블록 7): 검증 111.8ms(85%) · 드래프트 12.8 · lm_head 6.0 ·
  나머지 <1ms. 드래프터 4bit 양자화로 12.8 → ≈3.5ms(0.76GB).
- **[I10]** 종단 실측 최고치: 4bit 타깃 0.87×(블록 2) · 8bit 타깃 0.78×(블록 3).
  같은 스택의 우리 MTP 는 8bit 에서 **+43%**(21.9 → 31.3).
- **[I11]** 제3자(X, @nacyotKim)는 같은 M3 Ultra 512GB 에서 MLX 4bit+DSpark **58 tok/s
  (피크 63)**, raw 34.9 를 보고했다. 우리 raw 는 37.5 로 그쪽보다 빠른데 DSpark 는
  재현되지 않는다.

## 추론 노드

- **[RA1]** [I7]+[I8] ⇒ 이 스택에서 **일괄 검증은 공짜가 아니다**. 투기 디코딩의 핵심
  전제가 성립하지 않으므로, 손익분기 수락 길이가 통상보다 훨씬 높다.
  블록 7 기준 (29.7+5·6+드래프트+lm)/29.7 ≈ 2.4 이상이 필요하다.
- **[RA2]** [I6]+[RA1] ⇒ 수락 2.3\~2.7 은 손익분기 근처이고, 드래프터 자체 패스
  비용이 얹히면 순-손실이 된다. 실측 0.78\~0.87×가 이와 정합한다.
- **[RA3]** [I9]+[I10] ⇒ 우리 MTP 가 이기는 이유는 수락률이 아니라 **드래프트가 거의

- **[RA4]** [I7] ⇒ MTP 가 k=1 에서만 이겼던 종전 결과도 같은 곡선으로 설명된다.

## 충돌 노드

- **[CA1]** 참조 구현은 드래프트 출력을 `[:, -B+1:]`(각 마스크 슬롯의 출력이 그 슬롯을
  디노이즈)로 잘라 같은 인덱스에 넣는다. **그대로 구현하면 수락률이 떨어진다** —
  코드 2.82 → 1.37, 한국어 1.91 → 1.46. 한 칸 밀어 읽는 쪽(`[:, :B-1]`)이 타깃에 더
  많이 통과한다. 미해결. 첫 슬롯이 MASK 출력 대신 **알려진 토큰**의 출력을 읽게 되는
  것이 이득이라는 가설이 있으나 검증되지 않았다.
- **[CA2]** "블록 폭을 넓히면 이득"이라는 통념은 여기서 기각된다([I7]). 수락은
  2.3→2.7 로 오르지만 검증 비용이 더 빨리 올라 종단은 단조 감소한다(0.87→0.38×).
- **[CA3]** "수락분 재투입이 병목"이라는 초기 가설은 기각됐다. 재투입을 다음 검증에
  합쳐 타깃 패스를 스텝당 1회로 줄였는데도 0.40× 로 변화가 없었다 — 합치면서 검증
  폭이 S-곡선의 비싼 구간(10\~13토큰)으로 들어가 이득이 상쇄됐다([I9]).
- **[CA4]** [I11] 과 [I10] 은 정면 충돌한다. 같은 하드웨어·같은 모델·같은 드래프터인데
  그쪽은 1.66×, 우리는 0.87×. 우리 raw 가 더 빠르므로 측정 기준의 문제는 아니다.
  그쪽 스택에서는 일괄 검증이 싸다는 뜻이고, 무엇이 다른지는 확인되지 않았다.
