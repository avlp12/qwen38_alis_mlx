# exp16_unsloth 적대적 반증 리뷰

대상: `DSPARK_FINDINGS.md` §"Unsloth Dynamic 3.0 해부와 이식"([I173]–[I181], [RA62]–[RA65],
[CA36]–[CA38])과 게시 예정 문서 `qwen38_alis_mlx/docs/bit-allocation.md`.

노드 ID 는 이 리뷰 안에서만 유효하다(캠페인 원장과 충돌하지 않도록 `X` 접두).
운영 데이터(경로·명령·해시)는 맨 뒤 부록에 plain block 으로 둔다.

---

## 0. 요약 — 무엇이 살아남고 무엇이 무너지는가

| 원래 주장 | 판정 |
|---|---|
| ① H(k/v/α/β→8, lm_head→5)가 크기 +1.7%에 KL −17.2/−15.3/−5.7% | **부호는 살아남음.** 다만 기준선 아티팩트가 표의 것과 다름(§3) |
| ② 크기-고정 imatrix 재분배(C 원시·C2 상대)는 진다 | **성립(C).** C2 는 **통계적으로 미판정**이며 "기각"은 과잉(§3) |
| ③ 따라서 이득은 재분배가 아니라 값싼 승격에 있다 [CA37] | **자기 데이터로 반증됨(§1).** 설계상 재분배 팔이 이길 수를 못 뒀다(§2) |
| ④ embed_tokens 3bit 강등은 순손실 [I179] | **거짓.** 같은 크기 비교에서 F가 B를 압도(§1) |

**결론을 실제로 위협하는 상위 3개**: §1(F=B 동일 바이트인데 F 압승) · §2(배낭이 lm_head 를
승격 불가) · §3(판정 통계의 이중잣대 + 기준선 아티팩트 교체).

## 1. [XCA1] "재분배가 진다"·"embed 강등은 순손실"은 자기 데이터가 반증한다

- **[XI1]** `q4graded_b` 와 `q4graded_f` 의 `total_size` 는 **16,394,118,624 바이트로 완전히
  동일**하다(부록 A). B = 균일4 + k/v/α/β→8. F = B + embed 4→3 + lm_head 4→5. 즉 F는
  **바이트 단위로 크기-고정된 재분배**다.
- **[XI2]** 같은 하네스·같은 창의 `kl_out/kl_q4graded_{b,f}.json`:

  | 비교(비대응) | en | ko | code | top-1(overall) |
  |---|---|---|---|---|
  | F − B | −0.00400 (**−9.64%**, −2.0σ) | −0.00356 (**−8.41%**, −2.7σ) | +0.00137 (+0.97%, +0.1σ) | 91.293 대 90.760 (**+0.53pp**) |
  | H − F | −0.00039 (−1.04%, −0.2σ) | −0.00123 (−3.18%, −1.0σ) | −0.00293 (−2.06%, −0.3σ) | +0.10pp |

- **[XRA1]** [XI1]+[XI2] ⇒ **크기를 1바이트도 늘리지 않은 재분배가 승격-만-한 팔을 en −9.6%,
  ko −8.4%, top-1 +0.53pp 로 이겼다.** [CA37]의 명제 "크기-고정 재분배는 이 컨테이너에서
  진다"는 이 한 쌍으로 반례를 갖는다. 게시 문서의 문장
  *"Do not pay for it by demoting `embed_tokens`; that was a net loss on every slice"* 는
  같은 표의 F 행과 정면 충돌한다 — F는 **en·ko 두 슬라이스에서 순이득**이고, 손해는 code
  한 슬라이스(+0.97%, 0.1σ)뿐이다.
- **[XRA2]** [XI2] ⇒ "순손실" 판정의 근거인 **H > F 는 세 슬라이스 모두 1σ 이내**(−0.2/−1.0/−0.3σ)
  인데, 무시된 **F > B 는 2.0σ·2.7σ** 다. 강한 증거를 버리고 약한 증거를 결론으로 삼았다.
  게다가 H는 F보다 0.97% 크므로 "H가 F를 이겼다"는 **크기를 통제하지 않은 비교**다.
- **[XRA3]** [XI2] ⇒ 올바른 해석은 "강등이 손해"가 아니라 **비트당 가치가 텐서마다 크게
  다르다**는 것이다. 실측 한계효용(비대응):
  - `lm_head` 4→5: +0.148 GiB 당 en −10.6% (H−B)
  - `embed_tokens` 4→3: −0.148 GiB 당 en +1.0% / ko +3.2% (F−H)
  즉 두 텐서의 비트-가치가 **약 3–10배** 차이 나므로 교환은 강한 순이득이다. 이것은
  "재분배 무용"이 아니라 **재분배가 통하는 정확한 조건**을 보여준다.

**참이면 결론이 어떻게 바뀌나**: [CA37]과 [RA65]("이식 가능한 것은 값싼 텐서 목록이지
배분 알고리즘이 아니다")는 "우리 배낭의 목적함수가 틀렸다"로 축소된다. 게시 문서의 권고
문장은 삭제·수정이 필요하다(현재 상태로 게시하면 자기 표에 의해 반증되는 문장을 싣게 된다).

**2시간 내 판정 실험 X1**: `kl_paired.py`로 `[q4v, q4graded_b, q4graded_f, q4graded_h]`를
한 프로세스에서 대응표본 측정(약 4모델 × 3슬라이스, 이미 4모델 상주 실적 있음).
`F−B` 대응 t 가 en/ko 에서 유의하면 [CA37]·게시 문장은 폐기.

## 2. [XCA2] 재분배 팔(C/C2)은 **설계상** 이길 수(lm_head 승격)를 둘 수 없었다

- **[XI3]** `imatrix_ex2.json` 은 496 엔트리 전부 `blk.*` 이며 **`output.weight`(lm_head),
  `token_embd.weight`, `blk.64.nextn.eh_proj.weight` 가 없다**(부록 B).
- **[XI4]** `alloc.py` 는 imatrix 미커버 텐서를 `dropped` 로 빼고 `PIN_BITS=4`로 고정한다.
  재현 결과 **dropped = 94텐서 = 파라미터의 11.9%**이며 그 목록에 **lm_head · embed_tokens ·
  mtp.fc · MTP 블록 7텐서 · 비전타워 84텐서**가 모두 들어 있다. `alloc_c.json`/`alloc_c2.json`
  의 lm_head·embed 값은 실제로 둘 다 `4` 다.
- **[XRA4]** [XI3]+[XI4] ⇒ **C/C2 는 lm_head 를 올리는 수를 물리적으로 둘 수 없었다.**
  그런데 H 이득의 대부분이 정확히 그 수에서 나온다(B −6.0% → H −16.0%, 즉 승격 이득의
  약 2/3이 lm_head 4→5). 배낭이 F/H 를 재발명할 가능성은 애초에 0이었다.
- **[XRA5]** [XRA4] ⇒ [CA37]의 정확한 진술은 "크기-고정 재분배가 진다"가 아니라
  **"파라미터의 88.1%만 놓고, 목적함수를 텐서별 가중 제곱오차로 잡고, 가장 값비싼 수를
  제외한 배낭은 균일 4bit 를 못 이겼다"**이다. 일반화 범위가 크게 줄어든다.
- **[XRA6]** 목적함수 자체도 두 판본 모두 **[CA36]이 스스로 밝힌 층-간 증폭을 모델링하지
  않는다**. raw 는 절대 에너지, rel 은 오차/신호 — 둘 다 "앞층 오차가 60블록을 통과하며
  증폭된다"는 [CA36]의 진단을 목적함수에 반영하지 않았다. 시도한 가중이 2개인데
  "재분배가 진다"로 일반화한 것은 표본 2의 귀납이다.

**참이면 결론이 어떻게 바뀌나**: "imatrix 는 목록을 *확인*해 줬을 뿐 *계산*해 주지
못한다"[RA65]는 **미검정**으로 내려간다 — imatrix 배낭에게 lm_head/embed 를 준 적이 없기
때문이다.

**2시간 내 판정 실험 X2**: `alloc.py` 를 `PIN` 대신 **미커버 텐서를 균일가중(w=1, sens.py
가 이미 `imatrix:"uniform"` 로 저장)으로 배낭에 포함**시켜 C3 배분을 뽑는다(순수 CPU,
분 단위). C3 가 lm_head↑ + embed↓ 를 스스로 선택하는지만 보면 [RA65]의 진위가 갈린다.
빌드까지 가면 약 25분 + KL 약 12분.

## 3. [XCA3] 판정 통계가 일관되지 않고, 대응표본 기준선이 표의 기준선과 다른 아티팩트다

### 3-a. 이중잣대

- **[XI5]** `kl_out/*.json` 의 주변(비대응) 블록 SE 로 계산한 유의도:
  - **C2 대 균일**: en +0.00161 (**+0.72σ**) · ko +0.00126 (**+0.93σ**) · code +0.00295 (**+0.25σ**)
  - **AWQ 대 H**: en −0.00233 (−1.26σ) · ko −0.00027 (−0.23σ) · code −0.00780 (−0.71σ)
  - (대조) C 대 균일: +3.3σ / +6.4σ / +3.7σ — 이쪽은 진짜 유의
- **[XI6]** `paired_bh.json` 에서 대응 SE 는 주변 SE 의 약 1/4(en 0.00038 대 0.00146).
- **[XRA7]** [XI5]+[XI6] ⇒ **같은 크기(약 1σ)의 차이를 놓고, 우리 빌드에 유리할 때는
  "within noise"(AWQ 대 H)로, 불리할 때는 "기각"(C2)으로 읽었다.** 두 판정 모두 대응표본
  하네스를 돌리면 뒤집히거나 확정될 수 있는데, **C2·F·AWQ 는 대응표본으로 재지 않았다.**
  대응 SE 를 대입하면 AWQ−H 의 en 차이는 t 약 −6 이 되어 "within noise" 는 거의 확실히
  거짓이고, C2 는 유의해질 수도 아닐 수도 있다.
- **[XRA8]** [XI6] ⇒ **[CA37]("기각")은 현재 제시된 통계로는 지지되지 않는다.** 0.7–0.9σ
  는 기각이 아니라 미판정이다.

### 3-b. 기준선 아티팩트가 표와 대응표본에서 서로 다르다

- **[XI7]** `paired_bh.json` 의 base 는 `q4v-fp16` 인데 [I177]/[I179] 표의 기준선은 `q4v` 다.
  두 디렉터리는 **패킹 가중치가 바이트 동일**(k_proj.weight sha256 앞 16자리
  `1c3439f553b99cb2` 일치, down_proj 도 일치)이고 **`scales`/`biases` 의 dtype 만 BF16 대 F16**
  으로 다르다. `total_size` 도 같다(16,293,193,184).
- **[XI8]** 그 하나의 차이로 KL 이 움직인다: en 0.04414→0.04402(−0.28%), **ko 0.04476→0.04312
  (−3.65%)**, code 0.14838→0.14693(−0.98%).
- **[XRA9]** [XI7]+[XI8] ⇒ ① **[I181]의 "균일 4bit 대비"는 표의 균일 4bit 가 아니다.**
  ② 모든 등급 빌드(B/C/C2/F/H/I)는 BF16 scales 인데 대응표본 기준선만 F16 scales 이므로,
  **비트 배분 효과와 스케일 저장 정밀도 효과가 반대 방향으로 섞여 있다.**
  ③ 더 중요하게 — **scales/biases 를 F16 으로 바꾸는 것은 크기 0바이트에 ko KL 약 −3.7%**
  로, **C2 가 진 폭(+2.8%)보다 크다.** 이 캠페인이 판정한 모든 배분 효과와 같은 크기의
  **공짜 레버가 검토조차 되지 않았다.**
- **[XI9]** 두 하네스는 정규화 정밀도도 다르다. `kl_eval.py:logprobs` 는
  `lg - mx.logsumexp(lg)` 를 **모델 출력 dtype(bf16)** 에서 계산한 뒤 fp32 로 캐스팅하고,
  `kl_paired.py:logprobs` 는 **fp32 로 먼저 캐스팅한 뒤** `log_softmax` 를 돌린다.
  `kl_eval.py` 도크스트링의 "KL 은 전 어휘 fp32 정확 계산" 은 정규화 단계에는 해당하지 않는다.
  (자체 추정으로 p-가중 기여는 KL 의 약 0.5% 이하라 [XI8]의 3.65%를 설명하지 못한다 —
  그래서 [XI8]의 주범은 스케일 dtype 일 가능성이 높다. 그래도 두 하네스의 수치를 한 표에
  섞으면 안 된다.)

**참이면 결론이 어떻게 바뀌나**: ① [I181] 표의 "균일 4bit" 라벨을 `q4v-fp16` 으로 정정해야
한다. ② [CA37]의 "기각"은 "미판정"으로 내려간다. ③ 권장 레시피에 **"scales/biases 는 F16 으로
저장"** 이 들어가야 하며, 이는 승격보다 먼저 시도할 무료 항목이다.

**2시간 내 판정 실험 X3** (한 번에 다 됨):
`kl_paired.py --ref src q4v q4v-fp16 q4graded_c2 q4graded_h q4graded_f` 1회 실행.
얻는 것 — (a) 스케일 dtype 단독 효과의 대응 t, (b) C2 대 균일의 대응 t(진짜 기각인지),
(c) F 대 B/H 의 대응 t(§1), (d) 두 하네스 차이의 분리(같은 아티팩트 q4v 를 두 하네스로 잰 값 비교).
소요: 5모델 × 3슬라이스 × 약 17창. 기존 3모델 실행이 약 40분이었으므로 약 70분.

## 4. 반증에 실패한 것들 (봤지만 결함 아님)

정직하게 기록한다 — 아래는 의심해서 실제로 계측했고 **결론을 위협하지 못했다**.

- **[XI10] 블록 자기상관/대응표본 유효성 — 문제 없음.** `paired_bh.json` 의 블록별 차이
  d = KL_t − KL_base 의 lag-1 자기상관은 en +0.053 / ko +0.111 / code +0.164 로 작다.
  4블록을 창 단위로 묶어 재검정하면 t 가 H: −19.8→−17.6(en), −30.3→−24.6(ko),
  −9.4→−9.0(code)로 **거의 그대로**다. 유효표본이 68이 아니라 17이라 해도 결론 불변.
  세 모델 상주 + 창마다 교대는 상태 공유가 없고 순서가 동일하므로 대응표본 전제도 성립한다.
  (문서의 "블록 68개/슬라이스"는 code 만 60개다 — 표기 정정 필요.)
- **[XI11] 블록 KL 의 두꺼운 꼬리 — 블록 수준에선 문제 없음.** 토큰 수준 median/mean 비가
  code 에서 약 600배지만, 512토큰 블록 평균의 왜도는 en 1.85 / ko 0.13 / code 0.47 로
  t검정이 무너질 수준이 아니다.
- **[XI12] 배낭의 예산 소진 — 문제 없음.** `alloc.py` 의 `if size + dc > budget: continue`
  는 힙에서 항목을 버리지만, 재현 결과 **미사용 예산이 raw 0.01 MB / rel 0.00 MB** 로
  사실상 완전 소진이고, 남은 예산으로 가능한 승격도 0건이다. rel 재현은 `alloc_c2.json` 과
  **590텐서 전부 일치**했다(구현 재현성 확인).
- **[XI13] 배분 미적용([CA38]류) 재발 — 없음.** 6개 빌드 전부 `config.json` 의 모듈별
  비트 분포가 `alloc_*.json` 과 정확히 일치한다(비전 84텐서를 뺀 506 기준: B 4:376/8:130,
  H 4:375/5:1/8:130, F 3:1/4:374/5:1/8:130, C2 3:9/4:363/5:9/6:24/8:101, C 3:135/4:103/5:181/6:87).
  텐서 shape 로도 재확인(H 의 k_proj [1024,1280]=8bit, lm_head [248320,800]=5bit).
- **[XI14] 교란 후보들 — 전부 대칭.** 6개 빌드 모두 tensors 2211 / quantized 506 /
  unquantized 431 로 동일하고, **비전타워와 MTP norm 은 어느 빌드에서도 양자화되지 않는다**
  (즉 `alloc_*.json` 의 비전 84항목은 무효 항목이며, 비전 보존 차이는 교란이 아니다).
  group_size 는 전 빌드 64. 크기는 균일 15.174 / B·F 15.268(+0.62%) / H 15.416(+1.60%) /
  I 15.564(+2.57%). [I177]의 "+1.7%"는 **양자화 대상 파라미터의 bpw 비**(4.577/4.50)
  기준이고, **파일 크기 기준으로는 +1.60%**다 — 보존되는 bf16 텐서 0.92 GB 가 희석하기
  때문이다. 두 기준을 문서에서 구분해 표기할 것.

## 5. [XCA4] KL 만으로 판정하는 것의 한계 — 실제로 어긋나는 지점이 있다

- **[XI18] 평균 KL 과 top-1 이 서로 다른 순위를 준다.** AWQ 대 H:
  평균 KL 은 AWQ 가 세 슬라이스 모두 낮은데, top-1 은 en 91.599 대 **91.691**,
  ko 90.760 대 **91.090** 으로 H 가 앞선다(code 만 AWQ 91.488 대 91.387).
- **[XI19] 평균 KL 과 중앙 KL 도 어긋난다.** en 중앙 KL: AWQ 0.011204 대 **H 0.010875**,
  ko: AWQ 0.013544 대 **H 0.012478**. 즉 **AWQ 의 평균 우위는 상위 꼬리에서 나오고,
  전형적 토큰에서는 H 가 낫다.** 균일 대비 H 의 개선은 평균 −16.0%이지만 중앙값 기준
  **−39.3%**(0.017904→0.010875)다.
- **[XRA10]** [XI18]+[XI19] ⇒ 게시 문서의 *"within noise of the AWQ build … and ahead of it
  on top-1"* 은 **두 지표에서 각각 자기에게 유리한 쪽만 골라 쓴 문장**이다. 게다가 top-1
  차이에는 불확실도가 전혀 붙어 있지 않다 — en 의 0.09pp 는 34,816토큰에서 순 31토큰

- **[XRA11]** 이 캠페인에는 **PPL 도 다운스트림 task-accuracy 도 없다.** GLM-5.2 캠페인에서
  "task-acc 를 반드시 실측한다"로 정리된 관례가 여기엔 적용되지 않았다. 배분 권고를

게시 문서에 두 지표를 병기한다.
